#+TITLE: universe-manager
#+PROPERTY: header-args :mkdirp yes

* What it is

=universe-manager= is a deterministic StarIntel actor (kind:
=deterministic-actor=, =llm: false=, provider =none=) that operates the
component universe through the tracked Prolog control plane in
=.prolog/=. It gathers machine facts, renders them as safely quoted
Prolog terms, asks the control plane for every decision, and never
invents a policy verdict of its own. No LLM is involved anywhere.

* Flow

#+begin_example
inspect -> discover -> propose -> apply -> CI runs -> gate -> merge (human/CI) -> promote
#+end_example

| Step      | Command                                      | Effect                                                                  |
|-----------+----------------------------------------------+-------------------------------------------------------------------------|
| inspect   | =universe-manager inspect=                   | list registered components with pins (=git submodule status=) and upstream heads (=facts/heads.pl= or =git ls-remote=) |
| discover  | =universe-manager discover=                  | JSON list of stale components as =c(Component, Pin, Head)= candidates   |
| facts     | =universe-manager facts=                     | regenerate =facts/{pins,heads,notes}.pl= (quoted, offline-safe)         |
| propose   | =universe-manager propose --components a,b= / =--all= | per-component admissibility via the control plane; writes revalidation notes for affected dependents; emits ={branch, changes, policy}= |
| apply     | =universe-manager apply proposal.json=       | creates =universe-update/<date>-<shorthash>=, checks out each target sha (=git -C components/X fetch origin <sha= + =checkout=), updates =.gitmodules= URLs if changed, =nix flake lock --update-input= for changed inputs, commits with a machine message, prints the new commit sha |
| gate      | =universe-manager gate <branch> [--checks-file f.json]= | records =facts/checks.pl= from CI status (gh lookup, or the explicit mapping) and evaluates =merge_allowed/1=; exits 0/1/2 |
| promote   | =universe-manager promote <from> <to> <revision>= | evaluates =deployment_allowed/2= (and staging/release policy for those targets); exits 0/1/2 |

Exit codes everywhere: =0= success, =1= policy-denied (denials printed as
JSON), =2= error.

* Control-plane invocation

All swipl processes run with cwd = repository root. The canonical
=swipl -q .prolog/cli.pl <cmd> ...= form cannot carry facts today:

- =universe.pl='s =load_facts/0= ends its loading clause in =fail/0
  behind a cut, so it always fails when a facts directory exists;
  cli.pl's argv directive then fails while swipl still exits 0.
- =scripts/collect-facts.sh= writes unquoted SHAs; digit-leading SHAs
  are invalid Prolog, which used to make =facts/*.pl= unloadable.

The actor therefore consults =.prolog/universe.pl=, then
=lib/facts_shim.pl= (which redefines only =load_facts/0= with a
succeeding =forall/2= loop), injects the real argv via
=set_prolog_flag(argv, [...])=, and then consults =.prolog/cli.pl= so
its own =run/1= dispatch makes the decision. =run_swipl/2= also refuses
to translate swipl's exit 0 into a YES when the cli.pl directive failed
(no silent false-YES). Policy logic itself is untouched and remains
entirely in the tracked control plane.

Quoting is security-relevant: cli.pl parses argv with =atom_to_term/3=,
so SHAs always travel as quoted atoms (a bare digit-leading SHA is a
syntax error; an uppercase-leading one would parse as a *variable* and
could falsely satisfy =known_pin/2=).

* Tests

=python3 tests/actors/test_universe_manager.py -v= builds a
throwaway fixture universe (two real component repos, real submodules,
the real control plane copied in, facts generated by the actor itself)
and drives the real swipl: inspect, discover, propose admissible,
propose denied on a forged From, gate green, gate red, promote
stage-skip denied, promote candidate->integration allowed. No network.

* Security notes

- The actor holds no admin credentials, tokens, or secrets of any kind;
  it shells out to =git=, =swipl=, and optionally =gh= with explicit
  argument lists (never =shell=True=).
- It NEVER merges, pushes, or touches protected branches. =gate= only
  evaluates and reports; merging stays a separate human/CI step.
- Facts files carry pins, heads, check results, and revalidation notes
  only — never credentials, never secret material.
- =apply= refuses proposals that are not =admissible= and refuses to
  proceed when the worktree pin has drifted from the proposal's From.
- CI status is never invented: without =--checks-file= and without a
  successful =gh= lookup, =gate= errors (exit 2) instead of guessing.
